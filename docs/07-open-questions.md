# 07 · 待决事项

> 这些还没定。每条写清"什么时候必须定"，避免在不该纠结的时候纠结。

## 1. 开源许可 —— ✅ 已定 AGPL-3.0

**决定**：AGPL-3.0。仓库根目录已放 `LICENSE`。

**理由**：这个产品本质是"跑在你自己机器上"，AGPL 的价值观和它一致；且能阻止有人拿去做闭源云服务。

**被否掉的**：MIT（最宽松，但别人可以直接拿去闭源卖）；双许可 AGPL + 商业（保留变现可能，但要维护两套授权，一个人成本太高）。

> 注意：AGPL 意味着**我们如果将来做云端托管，自己的改动也必须开源**；同时别人 fork 后做网络服务同样要开源。这是有意的。

## 2. 推送方案（v2）

| 选项 | 成本 | 覆盖 |
|---|---|---|
| 前台服务长连接 + 本地通知 | 0 | Android 全量；App 被杀就没了 |
| 自建 ntfy / Gotify | 一台 VPS，$3–5/月 | 全平台；需自建 |
| APNs + FCM | 免费，但要开发者账号 + 服务端 | iOS 必须；国内 Android 不可用 |
| 国内厂商通道 | 免费，但要开发者认证 + 上架 | 国内 Android 唯一可靠路径 |

**关键约束**：连接是端到端加密的，**推送 payload 只能放"有事件"，不能放内容**。锁屏显示"你有 1 个待审批"，点开才连上去拉详情。

**建议**：v1 不做；v2 先做自建 ntfy（成本最低、不依赖任何商店）；v3 再考虑厂商通道。

**必须定在**：阶段 2 开始前。

## 3. iOS 是否首发

| 选项 | 后果 |
|---|---|
| Android 独占 3–6 个月 | 集中精力，但放弃一部分用户 |
| 同时发 | 工作量 ×1.4，且 iOS 只有遥控器，体验不对等 |

**建议**：先 Android。iOS 用户在等待期可以用现成的远程客户端（生态里已有 3–4 个）。

**必须定在**：阶段 1 结束时。

## 4. 鸿蒙的形态

遥控器（ArkTS 薄客户端）还是本机引擎（Flutter-OH 或原生移植）？

**建议**：先遥控器。本机引擎那条路要跟 Flutter-OH 的 fork 线，一个人扛不住。

**必须定在**：阶段 2 之后。

## 5. 会话级工具裁剪：等上游还是 fork

这是预设体系的地基。DSH 现在的插件加载是 host 全局的。

| 选项 | 代价 |
|---|---|
| 等上游支持 | 不确定什么时候有 |
| fork 一份 dsh 自己改 | 要持续 merge 上游，长期负担重 |
| 先用 profile 过渡 | 体验打折，但不阻塞 |

**建议**：先用 profile 过渡（一个工作区一个 `$DSH_HOME`），同时向上游提需求。**别把架构赌在这一条上。**

**必须定在**：阶段 1 中段（做预设切换时）。

## 6. 是否复用 dsh-go 的代码

dsh-go 是 AGPL-3.0。**可以读、可以学，不能抄**——一旦抄了，整个项目就要跟着 AGPL，而且这本来就是另一个人的作品。

**建议**：只看它的 issue 和文档，代码自己写。它踩过的坑（targetSdk 压到 28、OEM 保活、无障碍语义）直接写进我们自己的方案里。

**已经定了**：不抄。（见 D 系列决策）

## 7. 换手机怎么办

配对方案没有云端账号，那用户换手机时密钥怎么迁移？

| 选项 | 问题 |
|---|---|
| 手动导出密钥（二维码/文件） | 简单，但用户会丢 |
| iCloud / 系统备份 | 跨平台不一致 |
| 不做迁移，重配 | 最省事，但体验差 |

**建议**：v1 做手动导出（一个加密的 `.dshpalm` 文件 + 二维码），够用。

**必须定在**：阶段 2 前。

## 8. 文档能力用 Python 还是原生库

| 选项 | 体积 | 能力 |
|---|---|---|
| rootfs 里的 Python（python-docx / openpyxl / pypdf） | +40–55MB | 完整，改起来快 |
| Kotlin 原生库（Apache POI 等） | 更大，且重 | 不划算 |

**建议**：Python。但注意它是"受限执行环境"——模型看不见 python，只能通过文档工具间接用。

**必须定在**：阶段 1 做文档切片时。

## 9. 要不要支持"旧安卓当服务器"

即：一台插着电的旧手机跑宿主，你的主力机连过去用。

有意思，但涉及长期后台保活、电池安全、远程触发权限。**建议不放进 v1，也不放进 v1 的叙事。**

## 10. 商业模式

先不考虑。但有两个早期决定会影响后面：

- 是否接受捐赠（影响是否要写 License 说明）
- 是否做云服务（影响是否要设计多租户）

**建议**：v1 不做任何商业化设计，保持"本地优先、不联网"的纯粹性。这是最值钱的差异化。

## 11. 遥测

默认开还是默认关？

**建议**：**默认关**。这个产品的卖点是"跑在你自己机器上"，默认收集数据会自己打脸。要做就做"手动导出诊断包"（用户主动发给你）。

## 12. 品牌注册

"锦囊"是通用词，显著性弱，第 9/42 类大概率被注册或会被驳回。

**建议**：不硬砸钱。靠"锦囊 + 装进口袋的智能体"做搜索占位。真要做大再考虑。
