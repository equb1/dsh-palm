# 27 · 剩余工作清单（M1 收尾 → M2/M3/M4）

## 0. 现在的基线

- 轻引擎：会话 / 流式 / 审批 / 提问 / 工具（bash、文件读写、docx/xlsx、生图），
  真机 PLR110 全链路通过；深链 `dshpalm://light?...` 可配置模型渠道；
- IFileSystem：Node + expo-file-system 双后端，真实 `<filesDir>/workspace`；
- 测试：`npm run verify` = typecheck + 78 条；
- 包体：JS 4.2MB / APK 14.7MB（含 docx/xlsx）；
- 未完成：PDF、真生图渠道、WebView 联动、完整引擎按需、账号/互联/小组件、iOS。

## 1. P0 · M1 收尾（建议下一轮做完）

### 1.1 PDF 生成（唯一硬缺口）

- **现状**：`pdf-lib` 没接。标准字体（Helvetica 等）不含 CJK，中文会变空白/乱码。
- **要做什么**：先拍板字体方案（见 §5 决策 D1），再实现
  `create_pdf`（复用 `create_docx` 的 blocks 结构）+ `read_pdf`（pdf.js 文本抽取）。
- **验收**：
  - 一份含中文标题/段落/表格的 A4 PDF，手机相册/文件管理器能打开；
  - 生成 + 读回文本一致；文件 ≤1.5MB/页均摊；
  - Hermes 真机生成 ≤2s（不含字体首次加载）。
- **依赖**：字体子集产物（构建期生成）；若走"运行时下载"还要网络与缓存策略。
- **估时**：字体方案 0.5d + 工具 1d + 真机 0.5d。

### 1.2 真生图渠道验证

- **现状**：生图工具与渠道配置已完成，真机用**假渠道**（mock 返回 1×1 PNG）验证。
- **要做什么**：用真实 OpenAI 兼容生图 Key 跑一次（`gpt-image-1`、Flux、
  或国内兼容渠道），确认 `b64_json`/`url` 两种返回、尺寸参数、失败文案。
- **验收**：真机生成一张 ≥1024px 的图并落盘，工具结果里的宽高正确。
- **风险**：不同服务对 `response_format` 支持不一；有的只给 `url`（需要二次下载+鉴权）。
- **估时**：0.5d（含一个渠道的适配）。

### 1.3 真模型 ttft 与异常路径复测

- **现状**：ttft 埋点已加，但只在本地假模型上量到 35–69ms；真模型那轮只记了总耗时。
- **要做什么**：真模型跑 3 类场景：正常流式、断网/超时、401/429；
  记录 `[light] ttft/stream` 与错误文案。
- **验收**：日志里有真模型 ttft；断网 30s 内给出人话错误且能重试；
  401 提示去实验室改 Key。
- **估时**：0.5d。

### 1.4 中文/空格文件名与路径边界

- **现状**：expo 的 `new File(root, ...segments)` 只验证了 ASCII 文件名 +
  中文内容；中文文件名、空格、`#`/`%` 还没测。
- **要做什么**：补 10 个边界文件名的生成/读取/删除；确认 URL 编码正确。
- **验收**：`报告 2026#1.docx` 这类名字在生成、读回、`ls` 都正常。
- **估时**：0.5d。

### 1.5 生成后的"打开/分享"

- **现状**：文档只落在工作区，App 里没有文件浏览/预览入口。
- **要做什么**：加一个最小文件面板（列表 + 打开），复用 `expo-sharing`
  或系统 Intent；或先只在工具结果卡片上加"打开"。
- **验收**：生成 docx/xlsx 后能从界面一键预览/分享。
- **估时**：1–2d（UI + 原生分享）。

## 2. M2 · WebView + 完整引擎 + 插件徽章

### 2.1 WebView 与 RN 的会话态联动（docs/25 第 3 条）

- **现状**：实验室能打开官方 web 前端，但 token 是从宿主日志里捞的，与 RN
  侧会话互不相通。
- **要做什么**：
  1. 宿主把 `web` 地址/token 通过协议暴露（capabilities 或方法）；
  2. 从 RN 点会话 → WebView 直达该会话；WebView 内切会话 → RN 回报；
  3. 生命周期（前台/后台、登录态变化）与 `WebSurface` 的清理。
- **验收**：两端点同一会话，消息在一边发出另一边能看到；杀进程后状态一致。
- **依赖**：完整引擎（2.2）或远端宿主已在线。
- **估时**：3–4d。

### 2.2 完整引擎按需启动 + 会话迁移

- **现状**：`startHost()` 只能手动点，引擎失败会一直失败；没有"能力路由"。
- **要做什么**：
  1. 工具调用发现缺能力（跑脚本/PDF/格式转换）→ 提示"切到完整模式"；
  2. 用户确认后启动 proot 引擎，把会话历史 + 文件引用迁过去；
  3. 失败回退到轻引擎，不丢当前回合。
- **验收**：从轻引擎会话一键切完整引擎继续同一话题；冷启动 ≤15s 有进度。
- **估时**：1 周。

### 2.3 插件徽章（把兼容矩阵变成产品能力）

- **现状**：`scripts/plugin-compat.ts` 能出 L0–L4 矩阵，App 里完全没有入口。
- **要做什么**：设置页加"插件兼容"列表（内置矩阵 JSON + 搜索）；每个插件
  显示「手机原生 / 手机完整 / 仅电脑」徽章；点击给判定理由。
- **验收**：搜 10 个常见包，徽章与矩阵一致；离线可看（内置快照）。
- **估时**：2–3d（数据管道 1d + UI 1–2d）。

### 2.4 轻引擎附件上传

- **现状**：`attachments.upload` 返回 unsupported；拍照/分享图片进不了轻引擎会话。
- **要做什么**：图片写入工作区 `uploads/`，消息里带文件引用；模型用现有
  `list_dir/read_file`（图片暂不支持视觉，先给"已收到图片"与路径）。
- **验收**：从系统分享/相册发图，工作区出现文件，会话里有可点开的引用。
- **估时**：1–2d。

### 2.5 轻引擎多提供商

- **现状**：只有一个文本渠道 + 一个生图渠道，配置在实验室/深链。
- **要做什么**：把 `providers.list/save/discover` 在轻引擎里实现（SecureStore
  存多个 Key），设置页复用现有 ProvidersCard；会话选择渠道。
- **验收**：配 2 个渠道（DeepSeek + OpenRouter），会话内切换并流式成功。
- **估时**：3d。

## 3. M3 · 账号 / 互联 / 系统入口

### 3.1 官方 OAuth 真机验证（R3'）

- **现状**：源码结论可行，但 Platform 是否接受手机 loopback 回调没实测。
- **要做什么**：App 内起 127.0.0.1 随机端口 + `/oauth/callback`，Custom Tabs
  打开授权，回调换 token 存 SecureStore；处理"用户拒绝授权"（源码不处理 error）。
- **验收**：真机跑通登录 → 能调模型；拒绝授权 10s 内回错误而不是等 600s。
- **估时**：3–5d。

### 3.2 LAN 直连（配对 + 会话索引同步）

- **现状**：配对码/共享密钥协议已冻结（docs/11），实现是"单机 WS + 手动地址"。
- **要做什么**：mDNS 发现、E2E 加密 WS、会话索引拉取、离线状态机。
- **验收**：两台设备同 Wi-Fi，扫码后 5s 内看到对方会话；电脑离线手机不受影响。
- **估时**：1–2 周。

### 3.3 系统入口

- **现状**：只有通知（点开回 App）+ 分享接收（冷启动）。
- **要做什么**：Android 小组件（最近会话/任务进度/一键语音/审批提醒）、
  悬浮球、QS 磁贴；通知点击直达会话/审批卡；后台分享（onNewIntent）。
- **验收**：锁屏看到"待审批"→ 点开直接是那张卡；小组件 30s 内刷新。
- **估时**：1–2 周。

## 6. 工程债 / 质量

| # | 债 | 影响 | 建议 |
|---|---|---|---|
| E1 | JS bundle 4.2MB，Metro 不拆包 | 首启/更新成本 | M2 做按需资源包（文档库/生图 SDK 拆出去） |
| E2 | 一个会话一个 run，无队列 | 两个会话同时跑会抢 CPU | M2 调度器：并发上限 + 排队 + 优先级 |
| E3 | 宿主缺口：会话删除、正文搜索 | 抽屉只能改名/归档 | 等上游接口或自建索引 |
| E4 | 沙箱只有 JS 层路径约束 | 不是安全边界 | 文档里别承诺；真要隔离走完整引擎 |
| E5 | 真机回归靠 adb 脚本 | 没有 CI 真机 | 保持 `scripts/device-*.ts`，发版前手动跑 |
| E6 | docs/18、20 有过时内容 | 新人上手踩坑 | 下一轮顺手更新 |
| E7 | 无性能基准 | ttft/自检只有单次数据 | 加 `scripts/bench-light.ts`（多次取 P50/P90） |

## 7. 建议顺序

1. **D1 拍板 → PDF 工具**（M1 收尾）；
2. 真生图渠道 + 真模型 ttft/异常路径 + 文件面板（P0 剩余）；
3. **插件徽章**（纯前端 + 已有矩阵，性价比最高）；
4. 附件上传 → 多提供商（轻引擎完整性）；
5. WebView 联动 + 完整引擎按需（M2 主线）；
6. 账号/互联/系统入口（M3）。

## 8. 交接：怎么跑

```bash
# 分支
git switch feat/m1-light-engine        # 7 个提交，M1 全部内容

# 验证
npm run verify                         # typecheck + 78 条

# 真机（Android，无线 adb）
node --import tsx scripts/mock-model-server.ts 8799            # 普通链路
MOCK_PLAN=docs node --import tsx scripts/mock-model-server.ts 8799   # 文档链路
node --import tsx scripts/device-m1-check.ts <apk>             # 自检 + 审批 + 提问
node --import tsx scripts/device-real-check.ts <apk>           # 深链 + 真模型/文档（env 传 Key）
```

构建注意：仓库路径太长会让 CMake 报 `build.ninja still dirty`，把工作区
robocopy 到短路径（如 `D:\dp`）再 `gradlew :app:assembleRelease`；
`debug.keystore` 需要 `keytool` 生成一次；真机测试包用独立
`applicationId`，验完记得改回并卸载。
