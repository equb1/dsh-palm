# 11 · 登录与配对

> 结论先说：**我们不做账号登录。** 手机要的不是"一个账号"，是"证明它是主人的设备"。

## 为什么不做账号

账号登录解决的是"在陌生服务器上认出你"。我们的链路里没有陌生服务器：

```
手机 ──直接连──▶ 你的电脑（桥）──本地──▶ 你的 dsh
```

凭据（模型 key、GitHub 登录、SSH 私钥）**全在宿主上**，手机一件都不该拿。所以手机只需要一件事：**证明自己是主人**。

## 别人怎么做的

| 方案 | 账号用来干什么 | 我们要不要 |
|---|---|---|
| **DSH 官方** | 登录 DeepSeek 账号，拿模型额度 | 不要。额度是宿主的事 |
| **dsh-go** | ① DSH Remote 中继账号（GitHub 登录）② SSH 密码/私钥 ③ 宿主上的模型凭据 | ①②③ 都不是"App 账号" |
| **我们** | 无账号，只有配对 | — |

dsh-go 那套里最像"登录"的是 **DSH Remote 的中继账号**——因为它的流量要过第三方服务器做 NAT 穿透，服务器必须知道你是谁。

**我们不走中继，所以没有这个需求。** 等哪天做"手机连不在同一局域网的电脑"，才需要引入账号（或者自建中继 + 同样的配对密钥）。

## 现在的实现（MVP）

桥启动时生成一个六位配对码，打印在终端：

```
  dsh-palm 真引擎桥
  WS     ws://localhost:8788/ws
  配对码  246810      <- 手机端要填这个
  上游   http://127.0.0.1:8899
```

App 里填「地址 + 配对码」，连接时把码拼在 URL 上：

```
ws://192.168.1.7:8788/ws?pair=246810
```

桥校验不通过就直接关闭连接，关闭码 `4001`，理由「需要配对码」。客户端收到 4001 会**停止重连**并提示，不会无限重试。

```ts
// engine/src/real/server.ts
const expected = options.pairCode ?? '';
if (expected.length > 0 && url.searchParams.get('pair') !== expected) {
  ws.close(4001, '需要配对码');
  return;
}
```

调试时可以 `DSH_PALM_NO_PAIR=1` 关掉鉴权——**只在本机**这么用。

### 验过的三条

```
不带配对码被拒: 需要配对码
错误配对码被拒: 需要配对码
配对成功 | 宿主: 真 dsh（桌面） | 预设: standard,ptc,minimal,cordis
```

## 这版的问题（别当成终态）

1. **配对码是长期共享密钥**。只要不改，任何知道它的人都能连。
2. **没有设备身份**。两台手机用同一个码，桥分不出谁是谁，也没法单独吊销。
3. **ws 是明文**。同一 Wi-Fi 抓包就能拿到码。
4. **码只存在内存里**。App 重启要重输。

## 下一版：一次性配对 → 设备密钥

```
1. 桥显示二维码 / 六位码（一次性，5 分钟过期）
2. 手机扫码 → 拿到 { url, pairCode } + 自己的公钥
3. 桥验证码，登记设备公钥，签发一个只能用一次的响应
4. 之后每次连接用设备私钥签名挑战，不再传配对码
5. 桥可以单独吊销某台设备
```

**手机是扫码的那一端**——电脑负责显示，手机负责扫。这和"电脑是宿主"的分工一致。

扫码需要相机，在 Expo 里是 `expo-camera`（Expo Go 里直接可用）。MVP 先用手输码，等相机接进来再换成扫码，**二维码内容是同一串**：

```
dshpalm://pair?url=ws://192.168.1.7:8788/ws&code=246810
```

## 和"多宿主"的关系

一个手机可能连多台宿主（家里的电脑、公司的服务器）。设备密钥是**每台宿主一把**，不要共用——一台被攻破不影响另一台。

配对关系存在手机本地（Keychain / Keystore），宿主那边存公钥。**没有任何一方需要知道对方的秘密。**
