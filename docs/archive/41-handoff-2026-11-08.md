## 0. 本轮修复

### 1. 桌宠自由拖动

- `CompanionPet` 加 `PanResponder`：移动超过 6px 才接管，跟手拖动；
- 松手后 `Animated.spring` 收敛，限制在屏幕 ±42%；
- 点击 reaction / 长按 HUD 仍保留；
- 真机验证：拖到屏幕中部成功。

### 2. 局域网扫描永远扫不到电脑

根因有三：

1. 电脑真桥实际监听 `8788`（也可能 8787），旧代码只探 8787；
2. mock 引擎也在 8787，会被误当电脑宿主；
3. 手机 activeNetwork 可能是 VPN/蜂窝（198.18/10.x），按它算网段永远错。

修复：

- `LanDiscovery` 同时探 `8788/8787`，再 HTTP `GET /health` 只接受 `{"bridge":"real"}`；
- Wi-Fi 接口 IP 优先，只接受私有网段（10/192.168/172.16-31），排除 198.18 VPN；
- 跳过手机自己的 IP，避免把本机 proot 桥扫成电脑；
- 同一 host 只保留端口更高的一条（8788 优先）；
- 真机扫描结果：只剩 `192.168.1.3:8788` 一条。

### 3. 经常掉线

- 远程 `EngineClient` 从 `autoReconnect:false` 改为 `true`，断线自动重连。

### 4. 完整引擎会话被当成电脑

根因：`connectLocal()` 也用 `attach(client, 'remote', ...)`，`engineKind` 只有
`remote/light`，本机 proot 和电脑无法区分；同时远程表单默认就是
`ws://127.0.0.1:8788/ws`，点“连接电脑”其实连的是本机 proot。

修复：

- `engineKind` 增加 `'proot'`；`connectLocal` 用 `attach(client, 'proot', 'proot')`；
- 本机完整会话标签显示“完整”，不再显示“电脑”；
- 远程表单默认值改为空；禁止把 `127.0.0.1/localhost/::1` 提交为电脑宿主；
- 打开会话时不再因为存在 `remoteHost` 就自动连电脑；
- UI cache 里的 loopback remoteHost 读取时直接丢弃。

真机验证：抽屉显示本机工作区 `/workspace`、会话标签“完整”，未再标“电脑”；
扫描只出现电脑 `192.168.1.3:8788`。

### 5. 远程连接复测

- 重新起电脑桥 `PORT=8788 npm run engine`，手机扫描后点 192.168.1.3:8788；
- 抽屉显示「已连电脑 (LAPTOP-LCQVC5QV)」，工作区是 `D:\ces-mobile` /
  `C:\Users\chenf\Documents\deepseek-harness\default-workspace`，会话标签“电脑”，
  证明不会再混入本机 `/workspace`；
- 远程会话可正常跑（顶部「完整模式」+ 宠物 working 气泡）。

### 6. 宠物位置持久化

- 拖动松手写 `SecureStore('dsh-palm.pet.position')`；
- 启动时读回并 `pan.setValue`；
- 真机验证：拖到中间 → force-stop → 重开，宠物仍在中间。
- HUD 的「当前模型渠道」按 `engineKind` 显示：电脑宿主 / 完整引擎 / 轻引擎。

### 7. App 内出现两只宠物

根因：开启「App 外显示」后，App 内 `CompanionPet` 和原生悬浮窗同时渲染。

修复（产品取舍：外置模式只保留原生那一只）：

- `floatingActive` 时隐藏 App 内宠物气泡/角色，只保留右上角小齿轮；
- 原生 `FloatPetService` 默认可见，开启后全场景只有一只；
- HUD 增加齿轮入口，避免长按被拖动手势抢走；
- ColorOS `Settings.canDrawOverlays` 误报时用 `AppOps` 兜底；`setFloatingPetEnabled` 不再硬拦；
- 真机验证：开启后 App 内只剩左上角原生宠物，回桌面同一只；关闭开关后 App 内宠物恢复。
