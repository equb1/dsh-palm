## 1. 本次完成（M2.5）

### 1.1 协议与宿主

- `providers.list`：回当前单渠道；`configured` 认 API Key 或账号 token；模型列表仍是当前模型。
- `providers.discover`：轻宿主实现，只收 OpenAI 兼容协议；同域名不填新 Key 时复用当前
  API Key / 账号 token，填了新 Key 用 `Authorization: Bearer` 拉 `/models`；解析
  `id` / `name` / `context_window|context_length`；空列表、非 2xx、超时都转人话错误。
- `providers.catalog` 仍为空（轻引擎没有 43 条目录）。
- 宿主侧 `providers.save` 仍显式 `unsupported`（真正入口在 App store，见下）。

### 1.2 保存（App 侧，单渠道）

- `engine/light/config.ts` 新增纯函数 `applyProviderSave(setup, draft)`：
  - 只收 custom + `openai-completions`；Base URL 必须 http(s)；至少一个模型；
  - 提交的模型里有当前模型就保持，否则取第一个（UI 是多选，轻引擎只认一个）；
  - API Key 留空沿用原 Key；账号模式同域名保存继续复用 `authMode/authToken`（I7）；
  - 换 Base URL 又没填 Key 直接拒绝，避免把账号 token 发到别的域名；
  - 账号模式但 token 丢了 → 明确提示重新登录，不生成无鉴权配置。
- `store.saveProvider` 在 `engineKind === 'light'` 时改走 `saveLightProvider`：
  `applyProviderSave` → `connectLight`（重建轻宿主、重连、成功才写 SecureStore）→
  `refreshProviders` + `refreshModels`；连不上时恢复内存里的旧 setup 并抛错，旧配置不被覆盖。
- `ProvidersCard` 轻引擎下：隐藏目录/新增/删除，只留单渠道「编辑」；提示文案改成单渠道说明；
  `discover` 会把同域名的当前模型并入候选并勾选（账号 `/models` 已不列 `deepseek-chat`，
  否则「获取模型 → 保存」会静默换模型）。
