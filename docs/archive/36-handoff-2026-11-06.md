### 1.5 M2.7 追补：切回轻引擎刷新账号 token

- 旧逻辑 `resolveLightSetup` 用 `setup.authToken ?? loadAccountToken()`，缓存里的旧 64 字符
  token 会挡住浏览器 OAuth 重登后的新 token，切回轻引擎仍 401，只能重启 App。
- 新增 `withFreshAccountToken(setup, token)`（`engine/light/config.ts`）：账号模式每次重连
  优先用 `loadAccountToken()` 的新值，读不到才回退缓存；普通 API Key 渠道不碰。
  `resolveLightSetup` 改用它；单测 4 条。
- 仍受“需要用户真的完成一次浏览器授权”限制，本轮没走 OAuth 真机闭环，只补了代码路径。

### 1.7 修掉 Metro 的 self require cycle 警告

- 现象：每次冷启动 LogBox 都弹 “Open debugger to view warnings”，Metro 控制台是
  `Require cycle: src/engine/light/transport.native.ts -> src/engine/light/transport.native.ts`。
- 原因：native 文件从 `'./transport'` 取 `SSE_IDLE_TIMEOUT_MS`/类型，Metro 在原生平台把
  `'./transport'` 解析回 `transport.native.ts` 自己。
- 处理：拆出 `engine/light/transport.shared.ts`（常量 + `SseRequest`/`SseHttpResult`），
  `transport.ts` 重导出保持兼容，native 只从 shared 取。
- 验证：清缓存重启 Metro + 冷启动，警告 toast 消失，Metro 不再打印 require cycle；
  typecheck / verify 全绿。

### 1.34 release 发消息报错的根因与修复

- 现象：release 完整引擎发消息 1 秒后「出错」；首页曾显示
  `workspace/initializeDefault -> gateway/internal | Command failed: xdg-user-dir DOCUMENTS`。
- 根因 1：patch 资产在 Windows checkout 成 CRLF，`/usr/local/bin/xdg-user-dir` 是 shim，
  dash 解析报 `word unexpected`。修复：patch 全部转 LF、加 `.gitattributes`；
  `ensureShims` 每次宿主启动强制重写，`prepare` 不再用 `&&` 串联（避免前面失败跳过 shim）。
- 根因 2：完整引擎 catalog 的 default provider 是 `deepseek-official`（需要
  `DEEPSEEK_API_KEY`），账号登录后真正可路由的是 `deepseek-account`；会话因此报
  `MISSING_CREDENTIAL`。修复（`engine/src/real/server.ts`）：
  - 新会话创建后选第一个可路由模型；
  - 发消息前检查会话 modelSelection，provider 不可路由就自动切到 `deepseek-account`；
  - `models.list` 的 default 也只返回可路由 provider。
- 重新打包 bridge + release + `install -r` 后真机：完整引擎 `hi` 正常回复（V4.1-Flash，
  思考 + 正文流式）；发送报错修复。
