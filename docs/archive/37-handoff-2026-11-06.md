## 2. 这轮修掉的三个 release 专属坑

### 2.1 完整引擎卡 95%（cleartext）

- 现象：release 完整引擎一直「正在启动本机桥接 95%」，90s 后回轻引擎。
- 根因：release manifest 没有 `android:usesCleartextTraffic`，Java 健康检查访问
  `http://127.0.0.1:8788/health` 被系统拦掉；debug manifest 允许，所以只在 release 复现。
- 修复：`app/src/main/AndroidManifest.xml` application 加 `android:usesCleartextTraffic="true"`；
  `PROOT_BOOT_TIMEOUT_MS` 90s→180s（首启解压 rootfs 慢）。

### 2.2 发消息报错：patch 脚本 CRLF

- 现象：`workspace/initializeDefault -> gateway/internal | Command failed: xdg-user-dir DOCUMENTS`，
  `/usr/local/bin/xdg-user-dir: 8: Syntax error: word unexpected`。
- 根因：`assets/patch/*` 在 Windows checkout 成 CRLF，shim 脚本被 dash 解析失败；
  且旧 `prepare` 用 `&&` 串联，前一步失败会跳过 shim 同步。
- 修复：
  - patch 全部转 LF；新增 `.gitattributes`（`assets/patch/** text eol=lf`）；
  - `RuntimeInstaller.ensureShims` 每次启动强制重写；
  - `HostService` 的 `prepare` 不再用 `&&`，每一步都执行。

### 2.3 发消息报错：完整引擎默认模型不可路由

- 现象：release 完整引擎发消息 1 秒「出错」；日志 `llm-deepseek: no API key for provider route
  "deepseek-official"` / `MISSING_CREDENTIAL`。
- 根因：catalog 的 default 是 `deepseek-official`（需要 `DEEPSEEK_API_KEY`），账号登录后真正可路由的
  是 `deepseek-account`；新建会话直接用了不可路由 default。
- 修复（`engine/src/real/server.ts`）：
  - `sessions.create` 创建后选第一个可路由模型；
  - `sessions.send` 前检查会话 `modelSelection`，不可路由就自动 `session/selectModel` 到
    `deepseek-account`；
  - `models.list` 的 default 也只返回可路由 provider。
- 重新 `node scripts/build-bridge.mjs` + `assembleRelease` + `install -r` 后真机正常。
