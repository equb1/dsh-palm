## 1. 本轮完成

### 1.1 「在电脑继续」真机打通（43 的 P0 #1）

- 现场先复现失败：手机轻会话推送报
  `session/create -> agent-preset/not-found | Unknown agent preset: light`，电脑 tab 不增加。
- 原因：手机轻引擎的预设 id 是 `light`（还有只读等），电脑宿主是 `standard/ptc/minimal/cordis`；
  `pushSessionToComputer` 把 `detail.presetId` 原样传给 `sessions.create`，桥又原样塞进
  `session/create`，宿主直接拒绝。
- 修：
  - 桥 `engine/src/real/server.ts`：`sessions.create` 先 `resolveHostPreset()`——宿主有同名就透传，
    没有落 `agentPresets/list` 的 `isDefault`；返回的 `session.presetId` 用解析后的 id；
    宿主仍拒绝时抛人话「电脑宿主没有锦囊「x」，可用：…」而不是原始 RPC 串。
  - App `store.pushSessionToComputer`：先按电脑 `caps.presets` 挑同名 / 第一个，再 `create`。
- 结果：手机轻会话「帮我搜索一下乌克兰游戏地铁三部曲的…」推送成功；电脑 tab 会话数增加，
  电脑 DSH 侧生成真实会话并跑了 1 轮（测试后手动 `session/cancel`）。

### 1.2 推送会话的标题

- DSH 的 `session/create` 没有 title 参数，会拿第一条消息自动起名，于是电脑上出现
  `[dsh-handoff:h_…] 这是一次从…`。
- 修：App 发完 seed 立刻 `sessions.rename` 回手机标题（失败忽略）。实测立即改名不会被
  title-llm 覆盖（3/6/12s 复查仍是新名字）；真机会话标题变成
  「帮我搜索一下乌克兰游戏地铁三部曲的2…」。

### 1.3 顶栏角标 / 运行模式按 `link` 区分

- 连电脑宿主时 `engine.mode` 同样是 `full`，顶栏显示「完整模式」、运行模式页勾在「完整模式」上，
  和本机 proot 分不清。
- 修：`engineManager.badgeFor` 在 `link === 'remote'` 时返回「电脑」；`HomeScreen` 的
  `modeLabel` / `modeIsFull` 按 `link` 算，电脑用笔记本图标；运行模式页把「电脑宿主（已连接）」
  显示主机名 + URL 并打勾。
- 真机：首页角标「电脑模式」，运行模式页「电脑宿主（已连接）LAPTOP-LCQVC5QV · ws://192.168.1.3:8787/ws ✓」。

### 1.4 自动化长按的做法（工具坑）

- `adb shell input motionevent DOWN/UP` 分进程注入会把 RN 面板卡在“按下”，之后整块抽屉点不动；
  改用 `input swipe x y x y-4 1200`（同点 + 2–4px、1000–1500ms）能正常弹长按菜单。
- 见 PITFALLS I25；`uiautomator dump` 失败会返回旧 XML，别当现状，以截图为准。

## 4. 关键坑（新增）

1. **手机预设 id ≠ 电脑预设 id**：建会话前必须映射，否则 `agent-preset/not-found`（I24）。
2. **标题会被 seed 首行带偏**：推送后立刻 rename，别指望 `sessions.create` 收 title。
3. **adb 长按用 `input swipe`**，不要用两次 `input motionevent`（I25）。
4. **release 构建先清 Metro 缓存**：`npm run release:android`（否则可能打旧 JS）。
5. **无线调试端口每次变**：以手机「无线调试」页显示的端口为准。
